# File an idea

Turn a one-line idea into a filed, labelled GitHub issue, then hand it straight to `/triage`. **No building**: `/implement #N` builds it once it's `ready-for-agent`.

The idea is in the arguments. If there are none, ask for it in one line and stop.

## 1. Load the conventions

Read these before doing anything else:

- `docs/agents/issue-tracker.md`: how to talk to the tracker (`gh`)
- `docs/agents/triage-labels.md`: the label strings for each state role
- `CONTEXT.md` and any `docs/adr/` touching the idea's area (see `docs/agents/domain.md`)

If `docs/agents/issue-tracker.md` or `triage-labels.md` is missing, this repo isn't set up for these skills: stop and tell the user to run `/setup-matt-pocock-skills` first.

## 2. Check the code (read-only, keep it short)

Spend a few minutes, not a session. Two checks, same as `/triage`:

- **Redundancy**: search by domain concept, not just the idea's wording. Is this already built, fully or partly? Note where you looked.
- **Prior rejection / duplicates**: read `.out-of-scope/*.md` if it exists, and `gh issue list --state all --search "<key terms>"` for an existing issue.

Also note the **code areas** the idea touches (packages, types, entry points) so whoever picks it up has a starting point.

If it's already implemented, or an open issue already covers it: **stop and tell the user**, with the pointer. Don't file.

## 3. Pick the labels

Exactly one category and one state:

- **Category**: `enhancement` (new feature / improvement) or `bug` (something broken).
- **State**: `needs-triage` by default. Use `ready-for-agent` only if the user said so **and** the idea is concrete enough to write acceptance criteria without asking anything. If the user said so but it isn't, file as `needs-triage` and say why.

Map role names to label strings via `triage-labels.md`. If a label doesn't exist on the repo yet, create it (`gh label create "<name>"`) before filing.

## 4. Write and file the issue

Title: short, in `CONTEXT.md` vocabulary. Body (heredoc):

```markdown
> _This was generated by AI from a captured idea._

## Idea

<The user's idea, in their words, lightly cleaned up. Don't invent requirements.>

## Codebase notes

- **Already exists?** <no / partly: what and where>
- **Touches:** <domain concepts, types, packages>
- **Related:** <issues, ADRs, out-of-scope entries, or "none found">

## Open questions

- <Things `/triage` will need to settle. Questions only, no answers you guessed.>
```

For `ready-for-agent`, skip "Open questions" and add an agent brief as the first comment, following the template in the mattpocock `triage` skill's `AGENT-BRIEF.md`.

File with `gh issue create --title ... --body ... --label <category> --label <state>`.

## 5. Report

One line each: the issue URL and the labels. Don't ask follow-up questions about the idea here; triage does that next.

## 6. Triage it

If the issue was filed as `needs-triage`, immediately read the triage skill's `SKILL.md` and follow it for issue `#N`, resolving relative references (like `AGENT-BRIEF.md`) against its directory. Use the first one that exists:

1. `.claude/skills/triage/SKILL.md` or `.agents/skills/triage/SKILL.md` in the repo
2. `~/.claude/skills/triage/SKILL.md` or `~/.agents/skills/triage/SKILL.md`
3. `~/.claude/plugins/marketplaces/*/skills/engineering/triage/SKILL.md`
4. Otherwise search: `find ~/.claude ~/.agents -path '*/triage/SKILL.md' 2>/dev/null`, and pick the one whose frontmatter says `name: triage`

If none is found, end with the issue URL and the next command, `/triage #N`. Don't stop to ask whether to triage. Skip this step if it was filed `ready-for-agent`, and end with the next command, `/implement #N`.
